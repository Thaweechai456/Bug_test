P[82]: REFLECTION — ฉันเข้าใจ Data Flow Testing แล้วหรือยัง?
P[83]: 1. ก่อนทำกิจกรรมนี้ ฉันคิดว่า Test Case เกิดขึ้นจากอะไร?
P[84]: ก่อนทำกิจกรรมคิดว่า Test Case มาจาก requirement และสถานการณ์ที่ผู้ใช้อาจพบ
P[85]: ยังไม่ได้เชื่อมโยง Test Case กับตัวแปรและเส้นทางใน Source Code อย่างชัดเจน
P[86]: ตอนนี้จึงเห็นความสำคัญของการเริ่มจากข้อมูลในโปรแกรม
P[87]: 2. หลังทำกิจกรรมนี้ ฉันเห็นความสัมพันธ์ระหว่าง Source Code กับ Test Case อย่างไร?
P[88]: Source Code บอก Def/Use และ branch ส่วน Test Case เลือก Input เพื่อให้เดินผ่าน Path ที่ต้องการพิสูจน์
P[89]: phone เป็นตัวอย่างที่ทำให้เห็นความเชื่อมโยงจาก input ไปสู่ regex และผล validation
P[90]: ดังนั้น Test Case สามารถสร้างจากโครงสร้างของโปรแกรมได้
P[91]: 3. Def และ Use ช่วยให้ฉันมองหาเส้นทางทดสอบได้อย่างไร?
P[92]: Def ชี้จุดกำเนิดของค่า และ Use ชี้จุดที่ค่านั้นถูกตัดสินหรือใช้งาน
P[93]: จึงเลือก Path และ Test Data ให้ครอบคลุม true/false branch ได้
P[94]: สำหรับ phone จึงต้องทดสอบทั้ง 9 หลัก 10 หลัก และรูปแบบผิด
P[95]: 4. จุดไหนของกิจกรรมที่ฉันยังไม่เข้าใจ และต้องการให้อาจารย์อธิบายเพิ่ม?
P[96]: ต้องการให้อาจารย์อธิบายเพิ่มเรื่องการแยก C-use ในโค้ด JavaScript ที่เป็นการส่งข้อมูลมากกว่าการคำนวณ
P[97]: แต่เข้าใจ P-use ของ regex และ branch จากตัวอย่างนี้แล้ว
P[98]: จะใช้ตาราง Def/Use ช่วยตรวจคำตอบครั้งต่อไป
P[99]: 5. ถ้าต้องกลับไปทดสอบเว็บไซต์ของตนเองอีกครั้ง ฉันจะปรับวิธีคิด/วิธีทดสอบอย่างไร?

P[101]: จะทดสอบค่าขอบเขตและข้อมูลผิดควบคู่กับ happy path
